The Rust Programming Language

引用与借用

在 Listing 4-5 中的元组代码中存在的问题是，我们必须将 String 返回给调用函数，这样在调用 calculate_length 之后，我们仍然可以使用 String，因为 String 已经被移到了 calculate_length 中。相反，我们可以提供一个对 String 值的引用。引用就像指针一样，它是一个地址，我们可以通过这个地址来访问存储在该地址的数据；这些数据属于某个其他变量。与指针不同的是，引用在引用存在的时间内始终指向特定类型的有效值。

以下是如何定义和使用一个 calculate_length 函数的方法，该函数以对象引用作为参数，而不是直接拥有该值：

首先，请注意在变量声明和函数返回值中所有的元组代码都消失了。其次，请注意我们将 &s1 传递给 calculate_length，并且在 calculate_length 的定义中，我们使用的是 &String 而不是 String。这些冒号表示引用，它们允许你引用某个值而不需要拥有该值的所有权。图4-6展示了这个概念。

图4-6：&String s 的图表，指String s1

注意：使用 & 进行引用的相反操作是 反引用，这可以通过反引用运算符 * 来实现。我们将在第8章看到一些反引用运算符的用法，并在第15章中详细讨论反引用的细节。

让我们仔细看看这里的函数调用：

fn main() {
    let s1 = String::from("hello");

    let len = calculate_length(&s1);

    println!("The length of '{s1}' is {len}."。);
}

fn calculate_length(s: &String) -> usize {
    s.len()
}

&s1语法允许我们创建一个引用，该引用_指向s1的值，但并不拥有该值。由于引用并不拥有该值，因此当引用不再被使用时，它所指向的值也不会被丢弃。

同样，该函数的签名使用 & 来表示参数 s 的类型是一个引用。让我们添加一些解释性注释：

fn main() {
    let s1 = String::from("hello");

    let len = calculate_length(&s1);

    println!("The length of '{s1}' is {len}."。);
}

fn calculate_length(s: &String) -> usize { // s 是字符串的引用
    s.len()
} // Here, s goes out of scope. But because s does not have ownership of what
  // it refers to, the String is not dropped.

变量 s 有效的范围与任何函数的参数范围相同，但是当 s 不再被使用时，引用所指的值并不会被丢弃，因为 s 并不拥有该值的所有权。当函数以引用而非实际值作为参数时，我们不需要返回这些值来归还所有权，因为我们本来就没有拥有该值的权力。

我们将创建引用的行为称为“借用”。就像在现实生活中一样，如果一个人拥有某物，那么你可以从他们那里借用它。借用结束后，你必须归还它。此时，你不再拥有它。

那么，如果我们试图修改我们正在借用的内容会怎么样呢？请尝试使用 Listing 4-6 中的代码。剧透一下：这样做是行不通的！

可变引用

我们可以通过对 Listing 4-6 中的代码进行少量修改，从而允许我们修改被借用的变量。这些修改使用的是 可变的引用：

首先，我们将s更改为mut。 然后我们创建了一个可变的引用与 &mut s ，我们叫做change 函数，并更新函数签名以接受一个可变的引用与 some_string: &mut String 。 这非常清楚地表明，change函数会变换它所借的值。

可变引用有一个很大的限制：如果您有一个可变的值引用，您不能对该值有任何其他引用。 试图创建两个可变引用的 s 代码将失败：

以下是错误信息：

$ cargo run
   Compiling ownership v0.1.0 (file:///projects/ownership)
error[E0499]: cannot borrow `s` as mutable more than once at a time
 --> src/main.rs:5:14
  |
4 |     let r1 = &mut s;
  |              ------ first mutable borrow occurs here
5 |     let r2 = &mut s;
  |              ^^^^^^ second mutable borrow occurs here
6 |
7 |     println!("{r1}, {r2}");
  |                -- first borrow later used here

For more information about this error, try `rustc --explain E0499`.
error: could not compile `ownership` (bin "ownership") due to 1 previous error

这个错误表明这个代码是无效的，因为我们不能一次多次借s。 第一个可变借款是在 r1 中，必须持续到它在 println! 但在这种可变参照的创建与使用之间， 我们试图在 r2中创建另一个可变的引用，它借用了与r1` 相同的数据。

阻止多处可变引用相同数据的限制允许突变，但是控制得很严。 这是新的Rustaceans与之斗争的东西，因为大多数语言让你在你喜欢的时候变换。 使用这种限制的好处是Rust可以在编译时阻止数据竞赛。 一个 data 竞标 类似于一个种族状况，在这三种行为发生时发生：

  • 两个或多个指针同时访问相同的数据。
  • 至少有一个指针被用来写入数据。
  • 没有同步数据访问的机制。

数据竞赛会导致未定义的行为，当您试图在运行时跟踪它们时，可能很难诊断和修复； 必须通过拒绝编译与数据竞赛的代码来防止这个问题！

一如既往，可以使用大括号来创建一个新的作用域，以允许拥有多个可变引用，只是不能 同时 拥有：

fn main() {
    let mut s = String::from("hello");

    {
        let r1 = &mut s;
    } // r1在这里超出了范围，所以我们可以在没有问题的情况下做一个新的参考。

    let r2 = &mut s;
}

Rust 强制执行一个类似的规则来合并可变和不可变的引用。此代码导致错误：

fn main() {
    let mut s = String::from("hello");

    let r1 = &s; // 没有问题
    let r2 = &s; // 没有问题
    let r3 = &mut s; // BIG PROBLEM

    println!("{r1}, {r2}, and {r3}");
}

以下是错误信息：

$ cargo run
   Compiling ownership v0.1.0 (file:///projects/ownership)
error[E0502]: cannot borrow `s` as mutable because it is also borrowed as immutable
 --> src/main.rs:6:14

4 |     let r1 = &s; // no problem
  |              -- immutable borrow occurs here
5 |     let r2 = &s; // no problem
6 |     let r3 = &mut s; // BIG PROBLEM

  |                -- immutable borrow later used here

For more information about this error, try `rustc --explain E0502`.
error: could not compile `ownership` (bin "ownership") due to 1 previous error

轮子！我们_也不能有一个可变的参考值，但我们有一个不可变的同一值。

不可变参考值的用户不会指望该值会突然改变在他们的下面！ 然而，仍然存在着这种情况。 允许多个不可变的引用，因为任何只读数据的人都不能影响任何其他人阅读数据。

请注意，一个引用的范围始于引入的位置，并持续到最后一次使用该引用的时候。 例如，这个代码将被编译，因为不可变引用的最后一个用法是println!, 然后才引入可变的引用：

fn main() {
    let mut s = String::from("hello");

    let r1 = &s; // 没有问题
    let r2 = &s; // 没有问题
    println!("{r1} and {r2}");
    // 变量 r1 和 r2 在此后不会被使用。

    let r3 = &mut s; // 没有问题
    println!("{r3}");
}

不可变引用的范围在 r1 和 r2 之后结束 ！ 在最后使用的地方，它是在可变参考r3之前创建的。 这些范围不会重叠， 允许此代码: 编译器可以告诉, 在范围结束前的某一点, 不再使用该参考文献。

即使借款错误有时可能令人沮丧。 请记住，它是Rust 编译器提早指出潜在的 bug (在编译时间而不是运行时间)，并向您展示问题的确切位置。 然后，你不必追踪你的数据为什么不是你认为的数据。

悬空引用

在带指针的语言中， 很容易错误地创建一个 dangling pointer——一个指针，在可能给他人的内存中引用一个位置——在保存指针时释放一些内存。 与此相对照，在Rust, 编译器保证引用永远不会变得漂亮：如果你有某些数据的引用的话。 汇编器将确保数据在提及数据之前不会超出范围。

让我们更仔细地看看我们danger代码的每个阶段发生的事情：

因为s是在 dangle 里创建的，当danger 的代码完成时，s 将被移除。 但我们试图回过头来提到它。 这意味着这个引用会指向一个无效的 String 。这是不好的！请不要让我们这样做。

这里的解决方案是直接返回 String ：

    let string = no_dangle();
}

fn no_dangle() -> String {
    let s = String::from("hello");

    s
}

此操作没有任何问题。所有权被移除，没有任何被移除。

引用的规则

让我们概括一下之前对引用的讨论：

  • 在任何时候，你可以拥有一个可变引用，或者任意数量的不变引用（但不能同时拥有两者）。
  • 引用必须始终有效。
