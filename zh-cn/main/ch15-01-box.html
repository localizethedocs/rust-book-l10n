使用Box<T>指向堆上的数据

最直截了当的智能指针是一个方框，其类型是写入的 `Box’。 Boxes 允许您在堆栈上存储数据。 堆栈中剩余的是堆数据指针。 请参阅第4章，以审查堆栈和堆栈之间的差额。

盒子除了将数据存储在堆栈上而不是存储在堆栈上外，没有性能开销。 但他们也没有很多额外的能力。你会在这些情况下最经常地使用它们：

  • 当您有一个在编译时无法知道大小的类型， 并且你想要在需要精确大小的环境中使用该类型的值
  • 当您拥有大量的数据时， 您想要转移所有权，但确保数据不会被复制
  • 当你想要拥有一个值时， 而且你只关心它是一个实现特定特性而不是特定类型的类型

我们将在“使用盒子实现递归类型”中演示第一种情况。在第二种情况下，由于数据在栈上被多次复制，因此转移大量数据的所有权可能需要很长时间。为了提高性能，我们可以将大量数据存储在堆中的盒子里。这样，只有少量的指针数据会在栈上被复制，而它引用的数据则保持在一个位置上的堆中。第三种情况被称为“特质对象”，第18章中的“使用特质对象来抽象共享行为”专门讨论了这一主题。所以，你在这里学到的知识可以在那一部分中再次应用！

启用递归类型用框

一个 recursive 类型 的值可以作为其本身的一部分具有另一种类型的值。 递归类型会引起问题，因为Rust 需要在编译时了解一种类型占用多少空间。 然而，递归类型的价值嵌套理论上可以无限地继续下去，因此Rust 无法知道价值所需的空间有多大。 由于方框的大小已知，因此我们可以通过在递归类型定义中插入一个方框来启用递归类型。

作为递归类型的示例，让我们探索圆锥体列表。这是一个常见于函数编程语言的数据类型。 我们将定义的 cons 列表类型是简单的，除循环之外； 因此，当你进入涉及递归类型的更复杂的情况时，我们将与我们合作的样板中的概念将是有用的。

理解Cons列表

一个 cons 列表 是来自Lisp 编程语言及其方言的数据结构， 是由嵌套的对应体组成，是链接列表的Lisp版本。 它的名称来自Lisp中的cons函数(短于_construction function_)，它从它的两个参数中生成了一对新的函数。 通过在一个包含值和另一对值的配对上调cons，我们可以构造由递归配对组成的cons list。

例如，这里是一个包含列表1、2、3的圆括号中每对的伪码表述方式：

(1, (2, (3, Nil)))

每个条目都包含两个要素：当前条目的价值和下一个条目。 列表中的最后一个项目只包含一个叫做Nil的值，而没有下一个项目。 递归调用 cons 函数生成cons 列表。 典型的名称表示递归的基本案例为“无”。 请注意，这与第六章中讨论的“无效”或“无”的概念不同，这是一个无效或缺少的价值。

在Rust中，喜欢使用的 cons 列表不是一个常用的数据结构。 大多数时候你在Rust, Vec<T>都是一个更好的选择。 其他更复杂的递归数据类型 _是在各种情况下有用的，但从本章中的圆锥体列表开始， 我们可以探索框如何让我们能够定义递归性数据类型，而不要太分散。

计算非递归类型的大小

当我们讨论第6章中的枚举定义时，回顾我们在上架6-2中定义的 Message 序号：

enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
    ChangeColor(i32, i32, i32),
}

fn main() {}

确定分配给一个 Message 值的空间量 必须通过每个变量来查看哪个变量最需要空间。 Rust set that Message::Quit 不需要任何空格, Message::Move 需要足够的空间来存储两个i32 值等等。 因为只有一个变式将被使用， Message值所需的最大空间是它存储最大的变量所需的空间。

使用已知大小获取递归类型

因为Rust 无法为递归定义类型分配多少空间，编译器给出了一个有用的建议：

help: insert some indirection (e.g., a `Box`, `Rc`, or `&`) to break the cycle
  |
2 |     Cons(i32, Box<List>),
  |               ++++    +

在这一建议中，_indirection_意味着不是直接存储一个值， 我们应该通过存储指针到值来间接地存储值。

因为一个 Box<T> 是指针， 总是知道Box<T>需要多少空间: 一个指针的大小不会根据它指向的数据数量而变化。 这意味着我们可以将 Box<T> 放入变量内，而不是直接放置另一个 List 值。 Box<T>将指向下一个 List 值，这些值将放在堆上而不是放在cons变量内。 从概念上讲，我们仍然有一个名单，其中包括其他名单。 但这种执行现在更像把项目放在彼此之间，而不是放在彼此内部。
