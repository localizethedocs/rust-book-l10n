模块速查表

在我们了解模块和路径的细节之前，我们在这里提供了关于模块、路径如何的快速参考， use关键词和 pub关键词在编译器中工作，以及大多数开发者如何组织他们的代码。 我们将在整个本章中看到这些规则的例子， 但这是一个很好的地方，可以用来提醒我们模块是如何运作的。

  • 从 crate root 开始：编译时编译器在crate root 文件中首先看到(通常是 _src/lib)。 s_是要编译代码的库箱子和 _src/main.rs_是要编译的二进制箱子。
  • 声明模块：在crate root 文件中，你可以声明新模块；说你声明一个“花园”模块，使用 mod 花园; 。 编译器将在这些地方寻找该模块的代码：
    • 内嵌，用来替换mod garden后面的分号
    • 在文件 src/garden.rs
    • 在文件 _src/garden/mod.rs_中
  • 声明子模块：在除crate root以外的任何文件中，您可以声明子模块。例如，您可以在_src/garden中声明mod 蔬菜; 。 s_。编译器将在这些地方的父模块命名目录中寻找子模块的代码：
    • 内联方式，即直接跟随 mod vegetables，在花括号内而不是分号位置
    • 在文件 src/garden/vegtables.rs
    • 在文件 _src/garden/vegtables/mod.rs_中
  • 模块中代码的路径：一旦一个模块成为你的 crate 的一部分，你就可以在同一 crate 的其他位置引用该模块中的代码，只要符合隐私规则，并且使用正确的代码路径。例如，在 garden vegetables 模块中定义的 Asparagus 类型，其路径为 crate::garden::vegetables::Asparagus。
  • 私有与公有：默认情况下，模块内的代码对其父模块是私有的。要将一个模块设为公有，需要使用 pub mod 而不是 mod 进行声明。若要使公有模块中的项也变为公有，则需要在声明前使用 pub。
  • ** use 关键字**：在作用域内， use 关键字可以创建快捷方式，以减少重复编写长路径。在任何可以引用 crate::garden::vegetables::Asparagus 的作用域中，都可以使用 use crate::garden::vegetables::Asparagus; 创建快捷方式，之后只需使用 Asparagus 即可在作用域内使用该类型。

在模块中分组相关代码

Modules 让我们在crate 内组织代码, 以便可读性和易于重新使用。 模块还允许我们控制项目的 privacy ，因为模块中的代码默认是私有的。 私有项目是内部实现的详细信息，不供外部使用。 我们可以选择将模块及其内的项目公开发表，这使它们能够使用和依赖外部代码。

作为一个例子，让我们写一个提供餐馆功能的图书馆箱子。 我们将定义功能的签名，但是将其机构留空，以便集中精力组织守则，而不是实施餐馆。

在餐饮业，餐厅的某些部分被称为房顶，另一些则被称为房顶背部。 _居所前端_是客户所在的地方；这包括主机客户所在的地方，服务器接受订单和付款，以及酒吧做饮料。 回家是厨师和厨师在厨房工作，洗衣工清理，管理人员从事行政工作。

为了以这种方式安排我们的十字架，我们可以将其功能组织成嵌套模块。 通过运行 “货运新餐馆–lib” 创建一个名为“餐馆”的新图书馆。 然后，在列表7-1中输入代码到 src/lib.rs 来定义某些模块和函数签名；这个代码是房子区段的前面。

我们定义一个模块与 mod 关键字，然后是模块名称(这里是 front_of_house)。 然后模块的正文放在大括号内。 在模块中，我们可以放置其它模块，如“主机”模块和“服务”模块。 模块还可以包含其他项目的定义，如结构、枚举、常性、特征，以及清单7-1中的功能。

通过使用模块，我们可以将相关定义分组并命名为什么它们是相关的。 使用此代码的程序员可以浏览基于组的代码，而不必阅读所有定义， 使我们更容易找到与此相关的定义。 程序员在这个代码中添加新功能会知道在哪里放置代码来保持程序的组织。

早些时候，我们已经提到，src/main.rs 和 src/lib.rs 被称为_crate roots_。 其名称的原因是这两个文件中的任何一个文件的内容形成了一个模块，名为“crate`”，位于Crate模块结构的根目录下。 称为_module tree_。
