The Rust Programming Language

Rc<T>，一种基于引用计数智能指针

在大多数情况下，所有权是明确的：你确切知道哪个变量拥有某个特定值。 然而，在某些情况下，单一价值可能有多个所有者。 例如，在图表数据结构中，多个边缘可能指向同一个节点， 而且该节点在概念上为所有指向它的边缘所拥有。 节点不应被清理，除非它没有任何边缘指向它，因此没有拥有者。

您必须使用Rust type Rc<T>, 以明确方式启用多个所有权，这是_reference counting_的缩写。 Rc<T>类型将跟踪一个值的引用数量，以确定该值是否仍在使用。 如果一个值是零引用，则可以清理该值，而不会有任何引用变得无效。

想象一下Rc<T>作为家庭房间中的电视。 当一个人进入观看电视时，他们就把它关掉。其他人可以进入房间观看电视。 当最后一个人离开房间时，他们会关闭电视，因为它不再被使用。 如果有人在其他人仍在观看电视时关闭电视，就会有人从剩下的电视观看器中拔掉！

当我们想要在堆上分配一些数据以便阅读我们程序的多个部分时，我们使用Rc<T>类型。我们无法在编译时确定哪一部分将会用最后的数据来完成。 如果我们知道哪个部件将最后完成，我们只能让这个部分成为数据的所有者， 而且在编纂时强制执行的正常所有权规则将生效。

请注意，Rc<T>仅用于单线程场景。 当我们在第16章中讨论同义词时，我们将讨论如何在多线程程序中进行参考计算。

一致性变量拥有他们拥有的数据，所以当我们创建b列表时，a被移动到b和b拥有a时。 然后，当我们尝试在创建 c时再次使用 a时，我们不允许使用 a。

我们可以修改`一致性’的定义，代之以提及，但是我们必须指定终身参数。 通过指明生命周期参数，我们将指明清单中的每个元素至少与整个清单一样有效。 清单15至17所列内容和清单的情况就是如此，但并非在每一种情况下。

相反，我们将更改“List”的定义，使用“Rc”代替“Box，如清单15-18所示。每个“Cons”变量现在都将保存一个值和一个指向“List”的“Rc”。当我们创建“b”时，我们将克隆“a”所持有的“Rc”，而不是拥有“a”的所有权，从而将引用的数量从一个增加到两个，并让“a”和“b”共享“Rc”中数据的所有权。在创建c时，我们还将克隆a，将引用数量从两个增加到三个。每次我们调用Rc:：clone时，对`Rc中数据的引用计数都会增加，除非没有引用，否则数据不会被清理。

我们需要添加一条 use 语句，以便将 Rc<T> 纳入范围，因为它不在前文中。在 main 中，我们创建了一个包含 5 和 10 的列表，并将其存储在一个新的 Rc<List> 中，该 Rc<List> 又位于 a 中。然后，当我们创建 b 和 c 时，我们调用 Rc::clone 函数，并将 Rc<List> 的引用作为参数传递给 a。

我们本可以将 a.clone() 作为替代，而不是 Rc::clone(&a)。不过，Rust 的惯例是在这种情况下使用 Rc::clone。Rc::clone 的实现并不会像大多数类型对 clone 的实现那样，对所有数据进行深度复制。对 Rc::clone 的调用只会增加引用计数，这个过程并不需要花费太多时间。而深度复制数据则可能需要很长时间。通过使用 Rc::clone 来进行引用计数，我们可以直观地区分出那些需要深度复制的克隆对象，以及那些只是增加引用计数的克隆对象。在查找代码中的性能问题时，我们只需要考虑那些需要深度复制的克隆对象，而可以忽略对 Rc::clone 的调用。

克隆操作以增加引用计数

让我们修改 Listing 15-18 中的示例，这样我们就可以看到在创建和删除对 Rc<List> 的引用时，reference 计数是如何变化的。

在 Listing 15-19 中，我们将修改 main，使其在 list 周围有一个内部作用域。然后，我们可以观察到当 c 离开作用域时，引用计数会发生怎样的变化。

在程序的每个引用计数发生变化的点，我们都会打印出引用计数的值。这个数值是通过调用 Rc::strong_count 函数得到的。这个函数被命名为 strong_count，而不是 count，因为 Rc<T> 类型也包含 weak_count；我们将在“使用 Weak<T> 防止引用循环”中了解 weak_count 的用途。

这段代码会输出以下内容：

$ cargo run
   Compiling cons-list v0.1.0 (file:///projects/cons-list)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.45s
     Running `target/debug/cons-list`
count after creating a = 1
count after creating b = 2
count after creating c = 3
count after c goes out of scope = 2

我们可以看到，在 a 中，Rc<List> 的初始引用计数为 1；然后，每次我们调用 clone 时，引用计数会增加 1。当 c 超出作用域时，引用计数会减少 1。我们不需要像调用 Rc::clone 来增加引用计数那样，来调用函数来减少引用计数：Drop trait 的实现会在 Rc<T> 的值超出作用域时，自动减少引用计数。

在这个例子中，我们无法看到的是，当 b 和 a 在 main 结束时退出作用域时，计数变为0，而 Rc<List> 则被完全清理。使用 Rc<T> 则允许一个值拥有多个所有者，而计数则确保该值在任何一个所有者仍然存在的情况下仍然有效。

通过不可变引用，Rc<T>允许你在程序的多个部分之间仅进行数据读取。如果Rc<T>也允许使用多个可变引用，那么可能会违反第4章中讨论的借用规则之一：对同一位置进行多次可变借用会导致数据竞争和不一致性。不过，能够修改数据是非常有用的！在下一节中，我们将讨论内部可变性模式，以及你可以与Rc<T>结合使用的RefCell<T>类型，以配合这种不可变性限制来工作。
